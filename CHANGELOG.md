# Changelog

flakytest uses [calendar versioning](https://calver.org/): `YYYY.0bN` is the Nth beta of
the year, counting from 0 (`2026.0b0`, `2026.0b1`, … `2027.0b0`). Each section lists the
merged pull requests by category (or the commits, for changes pushed straight to `main`),
plus everyone who contributed to that release.

Notes under **Unreleased** are written by hand and become the "Highlights" of the
next release. Everything else is generated by `scripts/release.py` when a release is
prepared (see [RELEASING.md](https://github.com/anze3db/flakytest-python/blob/main/RELEASING.md)).

## Unreleased

- A run that never finished gets a report: when workers run out of memory and pytest-xdist hangs, or the run is
  killed, `flakytest list` shows it as unfinished and `flakytest report <id>` builds the report from what its
  processes recorded. When crashed workers had needed most of the machine's memory together, the report says they
  probably ran out of it and how many workers would fit.
- tachyon keeps sampling on macOS: it took pytest for gone a few seconds in, and the report spread those few seconds
  of samples over the whole run (a "29.9m startup" in a 5.5-minute run). A profiler that stops early is now
  reported, and when no test got a sample the report says sampling failed.
- tachyon's profiler process no longer grows with the run: it stays around 60 MB.
- "vs previous run" compares with the last run of the same tests, says when the selection or worker count differs,
  and counts the tests that ran but were skipped before (and the other way round).
- `flakytest pytest --help` (and `--fixtures`, `--markers`) no longer starts a profiling run.

## [2026.0b2](https://github.com/anze3db/flakytest-python/releases/tag/2026.0b2) - 2026-10-28

### Highlights

- **Breaking:** run your tests with `flakytest pytest [pytest arguments]`, which always profiles. Plain `pytest` no
  longer loads flakytest (the pytest plugin entry point is gone), and `flakytest run`, `--flakytest-profile` and
  `FLAKYTEST_PROFILE` are removed. Flaky test tracking with `FLAKYTEST_SECRET_TOKEN` also needs `flakytest pytest`
  now, so update your CI command. `--flakytest-rate`, `--flakytest-backend` and `--flakytest-output` still work, as
  pytest options.
- Profile unittest and Django tests without pytest: `flakytest python -m unittest …`, `flakytest python manage.py
  test …` (`--parallel` included). The report is the same as with pytest: tests named like pytest's, setUp/test/
  tearDown as the setup, call and teardown phases, `setUpClass`/`setUpTestData`/`setUpModule` and the test databases
  as shared fixtures, and suggestions that use `--keepdb` and `--parallel`.
- More accurate reports, from running 2026.0b1 on a 94,000-test Django suite:
  - Code that wraps other work (WhiteNoise and other middleware, freezegun, Celery's eager tasks, the debug
    toolbar, Hypothesis) only counts its own work, not everything under it.
  - `DEBUG = True` costs what Django's debug cursor adds to each query, and DEBUG is read while tests run;
    the database durability suggestion is based on the commits and writes outside a transaction it measured
    (none in a `TestCase`-only suite).
  - Network is real socket and TLS I/O only (an HTTP client parsing JSON is serialization), the garbage
    collector is recognised under tachyon, and categories are decided by context (imports, migrations, …)
    from the root, and otherwise by the deepest frame.
  - With tachyon, other threads are sampled while the main thread waits, so a thread pool's work shows up as
    that work instead of "waiting 100%".
  - Per-test memory is private memory, measured until the next test starts. Class, module and session
    fixtures keep their own memory and queries, so session setup queries no longer look like a test's N+1.
  - One-off warm-up (a fixture's first slow call in a process, imports) is set apart: the slowest tests are
    ranked without it, with a note, and the report has a "One-off costs" section.
  - A crashed pytest-xdist worker is reported, and its tests stay in the profile from what it recorded (or
    from pytest's reports).
- Much less overhead on large suites: each process builds its part of the profile in parallel and the
  controller merges them (a 20,000-test synthetic profile: about 50s before, 12s now), the profile is smaller
  (fast tests' call trees are folded into one suite-wide tree), the report loads `profile.js` instead of
  embedding a second copy, comparing with the previous run reads a small `summary.json`, and exact timings
  cost less per test. Big suites (over 10,000 tests) are sampled at 500 Hz, long tests at a quarter of the
  rate, and profilers run at a lower priority than the tests.
- `scripts/benchmark.py` (`just benchmark`) checks the overhead budget on a generated 5,000-test suite in CI.

### Changes

* Fix the migrations insight's total with xdist workers and its docs link
* Categorise samples by tier: GC first, context from the root, the rest from the leaf
* Count raw SQL per test, normalise it once per statement, and time commits
* Build each process's profile from a streamed stack tree and merge the parts
* Keep exact mode cheap and check the overhead budget in CI
* Allow migrate's own content type query in the session setup test
* Add benchmarks comparing py-spy and tachyon overhead, lost samples and bias
* Pin the benchmarks to the plugin version they measured
* Let the sampled tests pass when py-spy samples below its rate
* Update pre-commit hooks with Dependabot instead of pre-commit.ci
* Profile with `flakytest pytest`, and leave plain pytest alone
* Focus the README on profiling locally
* Move the profiling session out of the pytest plugin
* Profile unittest and Django tests with `flakytest python`
* Time post-processing from the last test on the xdist controller and Django's parallel parent

## [2026.0b1](https://github.com/anze3db/flakytest-python/releases/tag/2026.0b1) - 2026-10-18

### Highlights

- Profile your tests: `pytest --flakytest-profile` (or `flakytest run`) samples the whole session with
  tachyon (Python 3.15+) or py-spy, attributes every sample to a test and its setup/call/teardown, and
  writes a local HTML report: time by category (database, password hashing, network, sleep, fixtures,
  imports, …), the pieces of work in each test, hot lines in your code, call trees, fixture times and
  repeated SQL queries, for every test, class and file. No account needed.
- Ranked "fix next" suggestions with pytest, Django and SQLAlchemy perf tricks, each with the time it
  costs, the lines that trigger it and how to keep tests correct.
- The `flakytest` command: `run`, `report` (Markdown/JSON for people and coding agents), `compare`
  (speed and correctness between runs), `serve`, `list`, `upload`, `doctor`, and `mcp`, an MCP server
  over local runs.
- Memory per test: each test's peak above what its process had and what it kept, the tests that needed the
  most, each pytest-xdist worker's peak and (on Linux) all workers added up over time, and a warning when a
  process keeps growing. Exact per-test peaks need Linux; elsewhere install psutil for more detail.
- With `FLAKYTEST_SECRET_TOKEN`, profiles are uploaded to flakytest.dev, and runs report their
  environment (CI job or developer machine) and changed files.

### Changes

* Release with REST-only gh calls; --no-dry-run pushes
* Profile tests with a sampling profiler and report where their time goes
* Document profiling, the report, agent usage and the profile format
* Sharpen the report: shared fixtures, previous-run comparison, ORM-specific N+1 advice
* Install py-spy for development so the sampler tests run on every Python
* Keep the report fast on large suites and skip samples taken in the marker frame
* Test samples taken in the marker frame
* Report each test once under pytest-xdist
* Leave transaction statements out of repeated queries
* Send captured output and tracebacks only for tests that didn't pass
* Upload profiles in parts so large suites fit
* Document that profile uploads are idempotent
* Link the documentation on flakytest.dev from PyPI and the README
* Measure memory per test, per xdist worker and across workers
